# Кольцевая память AT24C32 — версия 160x15

Документ описывает **текущую реализацию** из `160x15.ino`. Это описание уже находящегося в коде механизма, а не новая спецификация.

## 1. Общая карта памяти

Используется AT24C32 объёмом 4096 байт. Адреса распределены без пересечения:

| Адреса (десятичные) | Размер | Назначение |
|---|---:|---|
| 0–1 | 2 байта | Старая контрольная сумма общих настроек |
| 2–39 | 38 байт | `general_setting`, прежний формат |
| 40–4007 | 3968 байт | 31 кольцо диапазонных настроек по 128 байт |
| 4008–4095 | 88 байт | Служебное кольцо последнего выбранного диапазона |
| **Всего** | **4096 байт** | Полная ёмкость AT24C32 |

Основные константы:

- `max_number_of_bands = 30`;
- `BAND_RING_COUNT = max_number_of_bands + 1`, то есть 31 кольцо;
- `BAND_RING_SIZE = 128`;
- `BAND_RECORD_SIZE = 15`;
- `BAND_LOG_RING_SIZE = 88`;
- `BAND_LOG_RECORD_SIZE = 3`.

Диапазонные кольца имеют индексы 0–30. Настройка меню `general_setting.number_of_bands` задаёт максимальный доступный индекс, а не количество в буквальном смысле: значение 0 даёт один диапазон (Band 0), значение 30 — 31 диапазон (Band 0…Band 30).

## 2. Общие настройки — прежний формат

Структура `general_set` занимает 38 байт. Её расположение и прежний способ контроля сохранены; это закреплено проверкой `static_assert(sizeof(general_set) == 38)`.

В первых двух байтах хранится старая контрольная сумма. Она вычисляется как сумма 38 байт структуры плюс поправка `crcmod`. В текущем исходнике:

```cpp
#define crcmod 7
```

При чтении общих настроек сумма проверяется до загрузки структуры. Если проверка не проходит, начальные значения структуры остаются в работе и записываются в основную область EEPROM.

Поле `general_setting.band` оставлено в структуре ради сохранения старого формата. Текущий рабочий диапазон хранится в отдельной глобальной переменной `band`. При сохранении общей структуры её старое поле `band` временно подменяется значением `memoryGeneralBand`, после записи исходное значение поля в RAM восстанавливается.

**Важно:** `crcmod = 7` относится только к старой контрольной сумме общих настроек. Новые кольцевые записи используют отдельный CRC-8 и от `crcmod` не зависят.

## 3. Диапазонные кольца

Для каждого Band выделено отдельное кольцо размером 128 байт. Начальный адрес кольца с индексом `index` вычисляется так:

```cpp
sizeof(general_set) + 2 + index * BAND_RING_SIZE
```

В начале кольца нет отдельного заголовка или таблицы указателей. Любая из 128 позиций может быть началом записи.

### Формат записи — 15 байт

| Смещение | Размер | Содержимое |
|---:|---:|---|
| 0 | 1 байт | Сигнатура `0xA0` + младшие 4 бита номера записи |
| 1–13 | 13 байт | Байтовое содержимое структуры `band_setting` |
| 14 | 1 байт | CRC-8 байтов 0–13 |

Размер структуры `band_set` закреплён проверкой `static_assert(sizeof(band_set) == 13)`.

Номер записи циклический, от 0 до 15. Он хранится в младшей тетраде первого байта; старшая тетрада должна соответствовать сигнатуре `0xA`.

### CRC-8 диапазонной записи

Используются параметры:

- полином: `0x07`;
- начальное значение: `0`;
- обработка старшим битом вперёд;
- отражение входа и выхода отсутствует;
- `xorout = 0`.

CRC считается по первым 14 байтам записи. При чтении запись принимается только при совпадении сигнатуры и CRC. В рабочую структуру `band_setting` байты копируются только после успешной проверки CRC.

### Поиск последней записи

При чтении выбранного кольца проверяются все 128 возможных начальных позиций. Если первый байт похож на сигнатуру, дочитываются остальные байты записи; чтение за концом кольца заворачивается к его началу через остаток от деления на 128.

Из корректных записей выбирается самая новая по циклическому 4-битному номеру. Разность номеров по модулю 16 от 1 до 7 означает, что кандидат новее текущего выбранного. Все 128 позиций просматриваются за один проход.

### Запись

Если корректная запись уже есть, следующая записывается со смещением 15 байт от начала последней записи, с переходом через конец кольца. Номер записи увеличивается по модулю 16. Если кольцо пустое, первая запись начинается с позиции 0 и имеет номер 0.

Сначала записываются 14 информационных байт, CRC записывается последним, пятнадцатым байтом. Затем все 15 байт перечитываются: проверяются побайтовое совпадение и CRC. Только после успешной проверки обновляется кэш последней записи.

### Пустое кольцо

Если в выбранном диапазонном кольце нет корректной записи, текущая структура `band_setting` **не инициализируется заново**. Её существующее содержимое сразу записывается в пустое кольцо с позиции 0 и номером 0. Это сохраняет прежнее поведение программы: при первом старте используются значения по умолчанию из объявления структуры, а при переходе на ещё не использовавшийся Band туда переносится текущее содержимое `band_setting`.

## 4. Служебное кольцо выбора диапазона №31

Последние 88 байт AT24C32 отведены под журнал выбранного Band. Запись занимает 3 байта; возможны 88 начальных позиций с циклическим переходом через конец кольца.

| Смещение | Размер | Содержимое |
|---:|---:|---|
| 0 | 1 байт | Сигнатура `0xA0` + номер Band в младших 5 битах |
| 1 | 1 байт | 8-битный номер события |
| 2 | 1 байт | CRC-8 первых двух байт |

В первом байте номер диапазона хранится в пределах 0–30. При поиске дополнительно проверяется, что найденный номер не больше `max_number_of_bands`.

Используется тот же CRC-8 с полиномом `0x07`. Служебное кольцо просматривается за один проход по 88 позициям. Для каждой подходящей сигнатуры читаются ещё два байта с циклическим переходом через конец кольца. После проверки CRC выбирается запись с самым новым 8-битным номером события: разность по модулю 256 от 1 до 127 означает, что кандидат новее.

При записи сначала сохраняются сигнатура с Band и номер события, затем CRC. После записи все три байта перечитываются и проверяются.

## 5. Последовательность работы

### Первый вызов `memory(MEM_READ)`

Первый вызов выполняется из `setup()`. Пока внутренний флаг `memoryInitialized` не установлен:

1. Загружаются общие настройки из области 0–39 с проверкой старой суммы и `crcmod`.
2. Рабочая переменная `band` получает начальное значение из сохранённого `general_setting.band`; недопустимое значение ограничивается нулём.
3. Сканируется служебное кольцо выбора Band. Если корректная запись найдена, она задаёт последний сохранённый выбранный диапазон.
4. Если служебное кольцо ещё не содержит корректной записи, исходный Band записывается в позицию 0 с номером события 0.
5. Устанавливается `memoryInitialized = true`.
6. Загружается диапазонное кольцо выбранного Band. Если оно пустое, в него записывается текущее содержимое `band_setting`.

### Последующие вызовы `memory(MEM_READ)`

При переключении Band энкодером меняется глобальная переменная `band`, затем вызывается `memory(MEM_READ)`. После первоначальной инициализации служебный журнал повторно не сканируется: загружается только кольцо текущего Band.

Само переключение Band не добавляет запись в служебное кольцо. Если кольцо нового Band пустое, в него записывается текущее содержимое `band_setting`, без повторной инициализации структуры.

### Вызов `memory(MEM_WRITE)`

Запись выполняется в следующем порядке:

1. Проверяется, что первичная инициализация памяти уже состоялась.
2. Сохраняются общие настройки в прежнем формате.
3. При необходимости находится последняя запись кольца текущего Band без загрузки её данных в `band_setting`.
4. Создаётся следующая запись диапазонных настроек. После её успешной записи и проверки создаётся следующая запись в служебном кольце с текущим номером Band.
5. Результат возвращается вызывающему коду.

Таким образом, один `MEM_WRITE` сохраняет общие настройки, текущие диапазонные настройки и выбранный Band.

### Автоматическое сохранение

Функция `storetomem()` ждёт более 10 секунд после последней активности энкодера. Запись выполняется, если установлен существующий флаг `actencf` и в данный момент нет передачи (`!txen`). Флаг очищается только при успешном результате `memory(MEM_WRITE)`.

При переключении Band сначала выполняется чтение нового кольца. Выбранный Band попадает в служебный журнал при последующем успешном `MEM_WRITE`, а не непосредственно в момент переключения.

## 6. Резервная копия во внутренней EEPROM микроконтроллера

Функции `backup()` и `restore()` работают с внутренней EEPROM МК, отдельно от внешней AT24C32:

- `backup()` записывает `general_setting`, затем `band_setting`, затем текущий `band`;
- `restore()` считывает эти же данные обратно, ограничивает номер Band допустимым диапазоном, вызывает `memory(MEM_WRITE)` и перезапускает МК.

В текущей реализации резервная копия **не имеет собственной CRC-проверки**. При `restore()` структуры считываются напрямую через `EEPROM.get()`; `crcmod` на этом этапе не участвует. После восстановления `memory(MEM_WRITE)` переносит полученные настройки во внешнюю AT24C32, где общая структура сохраняется с её прежней суммой, а диапазонные и служебные записи получают свои CRC-8.

## 7. Что важно помнить о текущей реализации

- Все 31 диапазонных кольцо зарезервированы в EEPROM независимо от того, сколько Band разрешено пользователю настройкой меню.
- В памяти хранится сырое байтовое содержимое `band_setting`; отдельной проверки разумности частот и режимов после CRC нет.
- Каждый успешный `MEM_WRITE` создаёт новую запись. Сравнения с предыдущим содержимым для пропуска дублей сейчас нет.
- CRC диапазонных и служебных записей не связана с `crcmod`.
- Вся внешняя работа с памятью вызывается через `memory(MEM_READ)` и `memory(MEM_WRITE)`; вспомогательные функции обслуживают внутреннюю раскладку и кольца.
