# План оптимизации формирования и проверки EEPROM-записей

## Цель

Устранить дублирование при формировании записей диапазонного кольца и журнала выбора диапазона, а также унифицировать установку и проверку CRC-8.

Оптимизация не должна менять формат EEPROM, адресную карту, алгоритм кольцевой записи, порядок физических записей или поведение Backup/Restore.

## Текущие форматы

### Диапазонная запись — 15 байт

| Байты | Назначение |
|---|---|
| 0 | Сигнатура `0xA0` и номер последовательности в младшей тетраде |
| 1–13 | Сырые байты структуры `band_set` |
| 14 | CRC-8 первых 14 байт |

Такая запись сейчас формируется отдельно в `memoryStoreBandRecord()` и `backupMakeBandRecord()`.

### Запись выбора диапазона — 3 байта

| Байты | Назначение |
|---|---|
| 0 | Сигнатура `0xA0` и номер выбранного диапазона |
| 1 | Номер события |
| 2 | CRC-8 первых 2 байт |

Формирование такой записи сейчас находится непосредственно в `memoryStoreSelectionRecord()`, а при Restore ожидаемая запись собирается повторно в `backupVerifyRestoredImage()`.

## План изменений

### 1. Общие операции CRC-8

Добавить небольшие функции для установки и проверки последнего байта CRC:

- установка CRC-8 по указанному количеству предшествующих байтов;
- проверка CRC-8 по тому же правилу.

Обе функции используют существующую `memoryCrc8()`. Сам алгоритм CRC-8 не переписывать.

Использовать их в поиске, записи и проверках обеих разновидностей записей там, где это делает код понятнее. Не менять дополнительные проверки сигнатуры, допустимого диапазона и последовательности: это отдельные правила формата.

### 2. Единый сборщик диапазонной записи

Создать общую функцию формирования 15-байтовой записи из:

- указателя на выходной буфер;
- номера последовательности;
- структуры `band_set`.

Функция формирует сигнатуру, копирует все 13 байт структуры и устанавливает CRC-8.

После этого:

- `memoryStoreBandRecord()` вызывает общий сборщик для текущей `band_setting`;
- код Backup вызывает тот же сборщик для переданной структуры настроек;
- отдельная `backupMakeBandRecord()` удаляется.

Формат записи и маска номера последовательности остаются прежними.

### 3. Единый сборщик записи выбора диапазона

Создать отдельную функцию формирования 3-байтовой записи из:

- указателя на выходной буфер;
- номера выбранного диапазона;
- номера события.

Использовать её в:

- `memoryStoreSelectionRecord()`;
- формировании ожидаемой записи выбора диапазона в `backupVerifyRestoredImage()`.

Проверки допустимости диапазона в поиске и валидации Backup/Restore оставить на своих местах.

### 4. Проверки CRC в существующих путях

Перевести повторяющиеся прямые сравнения CRC на общий помощник проверки там, где длина данных известна:

- поиск диапазонной записи;
- проверка записи после записи в кольцо;
- поиск записи выбора диапазона;
- проверка записи после записи в журнал;
- проверка диапазонных записей в Backup;
- проверка диапазонных и служебной записей после Restore.

CRC16 резервного слота не затрагивать: это другой алгоритм и отдельный формат.

## Что категорически не меняется

- `BAND_RECORD_SIZE == 15`, `BAND_LOG_RECORD_SIZE == 3`.
- Сигнатуры, маски и расположение байтов обеих записей.
- Алгоритм `memoryCrc8()` и его параметры.
- Алгоритмы поиска самой новой записи и сравнения номеров последовательности.
- Адреса, размеры и организация колец AT24C32.
- Порядок записи диапазонной записи: сначала 14 информационных байтов, CRC последним.
- Порядок записи трёхбайтовой служебной записи и последующее чтение для проверки.
- Логика и формат полного Backup/Restore, включая CRC16, маркер завершения и карту двух внутренних слотов.
- Содержимое существующих EEPROM и совместимость со старыми записями.

## Проверка после реализации

1. Сравнить формируемые байты диапазонной записи до и после оптимизации для одинаковых `band_set` и sequence.
2. Сравнить формируемые байты записи выбора диапазона для одинаковых band и sequence.
3. Убедиться, что все пути поиска и проверки по-прежнему отвергают неверную сигнатуру, недопустимый диапазон и неверную CRC.
4. Проверить, что пустые кольца и маркеры пустых диапазонов Backup остаются без изменений.
5. Проверить неизменность порядка записи данных и CRC в обеих функциях записи.
6. Выполнить компиляцию целевой прошивки и, после прошивки, проверить штатное чтение/сохранение, Backup, Restore и повторное чтение настроек.
