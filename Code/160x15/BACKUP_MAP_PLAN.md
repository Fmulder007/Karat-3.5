# План унификации карты внутренней EEPROM Backup/Restore

## Цель

Принять удачные решения из `160x15_BackupMap_patch.zip`, но интегрировать их в актуальный `160x15.ino` без замены скетча архивной версией. Устранить ошибку длины CRC и сделать раскладку двух слотов явно описанной, вычисляемой и защищённой compile-time проверками.

## Что принимается из архива

- Единое пространство имён `BackupMap` вместо набора разрозненных макросов `BACKUP_*`.
- Расчёт смещений последовательными выражениями: настройки, выбранный диапазон, записи колец, служебные поля, CRC.
- Статические проверки размеров и границ карты.
- Единая точка определения формата слота, чтобы адреса не расходились между Backup и Restore.

## Что исправлено

В архивном варианте было задано:

```cpp
CrcLength = CrcOffset; // 508
```

Это ошибочно включает байт маркера завершения по адресу 507 в CRC. Во время создания слота CRC рассчитывается до записи маркера (там находится `0x00`), а при последующей проверке маркер уже равен `0xA5`. Поэтому только что записанный слот не проходит проверку; кроме того, формат перестаёт быть совместим с уже существующими копиями.

Правильное правило:

```cpp
CrcLength = CommitOffset; // 507 байт: адреса 0..506
CrcOffset = CommitOffset + 1U; // CRC хранится по адресам 508..509
```

CRC не включает маркер завершения. Маркер `0xA5` по адресу 507 по-прежнему записывается последним и отдельно проверяется при чтении.

## Итоговая карта одного слота

Все адреса в таблице относительные, от начала выбранного слота.

| Смещения | Размер | Содержимое |
|---|---:|---|
| 0–37 | 38 байт | `general_set` |
| 38 | 1 байт | Выбранный диапазон |
| 39–503 | 465 байт | 31 запись колец по 15 байт |
| 504 | 1 байт | Сигнатура `0x4B` |
| 505 | 1 байт | Версия формата `1` |
| 506 | 1 байт | Номер слота: 1 или 2 |
| 507 | 1 байт | Маркер завершения `0xA5` |
| 508–509 | 2 байта | CRC16, младший байт первым |

| Слот | Абсолютные адреса | Размер |
|---|---:|---:|
| 1 | 0–509 | 510 байт |
| 2 | 510–1019 | 510 байт |
| Резерв | 1020–1023 | 4 байта |

CRC-16/CCITT-FALSE рассчитывается по 507 байтам с относительными адресами 0–506 включительно. Используются прежние параметры CRC и прежнее расположение поля CRC.

## Изменения в исходном коде

1. Заменить макросы карты адресов на `BackupMap`.
2. Перенести в карту размеры, смещения, маркеры и длину CRC.
3. Использовать имена карты во всех адресных обращениях Backup/Restore: начало слота, данные колец, выбранный диапазон, метаданные, commit marker и CRC.
4. Сохранить текущую реализацию CRC16 и порядок записи слота: сначала сброс маркера, затем данные и CRC, последним — `0xA5`, затем проверка готового слота.
5. Сохранить текущий четырёхстрочный журнал Backup/Restore и все текущие исправления основной ветки.

## Compile-time защита

В коде проверяются:

- размер `general_set` — 38 байт;
- размер записи диапазонного кольца — 15 байт;
- количество диапазонов — 31;
- начало служебных данных — 504;
- commit marker — 507;
- длина входа CRC — 507 байт;
- поле CRC — адреса 508–509;
- размер слота — 510 байт, двух слотов — 1020 байт;
- доступность двух слотов в EEPROM МК;
- отсутствие наложения соседних областей и совпадение конца карты с концом слота.

Проверки должны останавливать сборку при неожиданном изменении размеров структур или формата данных, а не допускать незаметного смещения резервного образа.

## Что не меняется

- Формат уже созданных резервных копий: версия остаётся 1, адреса и значения служебных полей прежние.
- CRC16/CCITT-FALSE и порядок байтов CRC.
- Ручной выбор двух слотов и их независимость.
- Алгоритмы поиска, формирования и кольцевой записи данных AT24C32.
- Содержимое и поведение текущего журнала Backup/Restore.
- Алгоритм восстановления и контроль данных внешней AT24C32.
- Пользовательское меню и назначение кнопок.

Не переносить скетч из ZIP целиком: архивная копия старее основной ветки и откатывает последующие изменения интерфейса Backup/Restore.
