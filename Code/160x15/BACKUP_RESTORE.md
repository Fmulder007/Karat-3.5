# Полный Backup/Restore: внутренняя EEPROM МК и AT24C32

Документ фиксирует согласованный план и реализацию полного резервирования для скетча `160x15.ino`.

Назначение: сохранить состояние радиостанции на момент запуска Backup, включая текущие настройки из RAM и самые свежие настройки всех диапазонов из внешней AT24C32, а затем уметь полностью восстановить это состояние. История кольцевых записей не сохраняется.

## 1. Основной принцип

Резервная копия состоит из:

1. Текущей структуры общих настроек `general_setting` из RAM.
2. Текущего выбранного диапазона `band`.
3. Ровно одной последней актуальной записи для каждого из 31 диапазонных колец AT24C32 (индексы 0…30).
4. Контрольных данных резервного образа.

Для активного диапазона источником является текущая структура `band_setting` в RAM: она приоритетнее последней записи во внешней EEPROM, поскольку в RAM могут находиться ещё не сохранённые изменения.

Для остальных диапазонов источником является последняя корректная запись соответствующего кольца AT24C32, найденная штатным алгоритмом `memoryFindBandRecord()`.

Резервирование не должно записывать или очищать AT24C32. Оно только читает внешнюю EEPROM и формирует копию во внутренней EEPROM МК.

Полная история колец не копируется.

## 2. Два ручных слота внутренней EEPROM

Используются два независимых слота. Никакого автоматического выбора, чередования или поиска самой новой копии нет.

Интерфейс функций:

```cpp
void backup(uint8_t slot = 1);
void restore(uint8_t slot = 1);
```

Поведение:

| Вызов | Результат |
|---|---|
| `backup()` | Запись в слот 1 |
| `backup(1)` | Запись в слот 1 |
| `backup(2)` | Запись в слот 2 |
| `restore()` | Восстановление из слота 1 |
| `restore(1)` | Восстановление из слота 1 |
| `restore(2)` | Восстановление из слота 2 |

Недопустимый номер слота не должен автоматически подменяться другим номером. Такая проверка нужна сейчас, а в будущем позволит добавить ручной выбор слота в меню без изменения формата резервной копии.

Существующие пункты меню пока не меняются: они продолжают вызывать функции без аргументов и работают со слотом 1.

### Карта внутренней EEPROM

Для ATmega328P доступно 1024 байта внутренней EEPROM.

| Адреса | Размер | Назначение |
|---|---:|---|
| 0–509 | 510 байт | Слот 1 |
| 510–1019 | 510 байт | Слот 2 |
| 1020–1023 | 4 байта | Резерв |

Расчёт одного слота:

| Содержимое | Размер |
|---|---:|
| `general_setting` | 38 байт |
| Текущий `band` | 1 байт |
| 31 запись диапазонных колец × 15 байт | 465 байт |
| Сигнатура | 1 байт |
| Версия формата | 1 байт |
| Идентификатор слота | 1 байт |
| Маркер завершённой записи | 1 байт |
| CRC16 | 2 байта |
| **Итого** | **510 байт** |

Два слота занимают 1020 из 1024 байт. Запас — 4 байта.

### Раскладка данных внутри слота

Все смещения указаны относительно начала выбранного слота.

| Смещения | Размер | Содержимое |
|---|---:|---|
| 0–37 | 38 | Сырые байты `general_setting` из RAM |
| 38 | 1 | Текущий `band` |
| 39–503 | 465 | 31 диапазонная запись по 15 байт |
| 504 | 1 | Сигнатура `0x4B` |
| 505 | 1 | Версия формата, первоначально 1 |
| 506 | 1 | Идентификатор слота: 1 или 2 |
| 507 | 1 | Маркер завершения `0xA5` |
| 508–509 | 2 | CRC16, младший байт первым |

Диапазонная запись номер `n` начинается со смещения:

`39 + n × 15`, где `n = 0…30`.

Если диапазонное кольцо пустое, его 15 байт в образе заполняются `0xFF`. Это специальный признак пустого диапазона, а не запись, предназначенная для помещения во внешнее кольцо.

### CRC16 и защита от прерванной записи

Используется CRC-16/CCITT-FALSE:

- полином: `0x1021`;
- начальное значение: `0xFFFF`;
- обработка старшим битом вперёд;
- отражение входа и выхода отсутствует;
- `xorout = 0`.

CRC рассчитывается по смещениям 0–506 включительно (507 байт). Маркер завершения на смещении 507 в CRC не входит. CRC хранится в смещениях 508–509, младший байт первым.

Последовательность Backup для выбранного слота:

1. Сбросить маркер завершения выбранного слота в недействительное значение.
2. Записать данные и служебные поля.
3. Рассчитать и записать CRC16.
4. Последним записать маркер `0xA5`.
5. Прочитать и проверить сформированный слот.

При отключении питания в процессе записи маркер не позволит принять незавершённый образ за действительный. Второй слот не затрагивается.

Проверка слота обязательно контролирует сигнатуру, версию, идентификатор именно выбранного слота, маркер, CRC16 и формат всех 31 диапазонных записей. При восстановлении из слота 1 нельзя автоматически переходить к слоту 2 и наоборот.

## 3. Формирование Backup

### 3.1. Общие настройки и выбранный диапазон

- `general_setting` копируется напрямую из RAM, без подмены поля `general_setting.band`.
- `band` копируется из текущей глобальной переменной.
- Активный `band_setting` используется непосредственно из RAM.

### 3.2. Активное диапазонное кольцо

Сначала штатным поиском определяется последняя запись активного диапазона и её номер последовательности.

В резервную копию формируется запись из текущего `band_setting` в RAM:

- сигнатура `0xA0` с младшей тетрадой номера последовательности;
- 13 сырых байт текущего `band_setting`;
- CRC-8 по первым 14 байтам.

Если в кольце была корректная запись, для снимка используется следующий номер последовательности по модулю 16. Если кольцо пустое — номер 0.

Это не записывает новую запись в AT24C32. После Backup штатный отложенный `memory(MEM_WRITE)` сможет записать текущее состояние в рабочее кольцо обычным способом.

### 3.3. Остальные диапазоны

Для каждого из остальных 30 диапазонов выполняется поиск самой свежей корректной записи штатным алгоритмом. В образ переносится вся запись размером 15 байт, включая её исходный номер и CRC-8.

Если все 128 байт кольца равны `0xFF`, в образ помещается маркер пустого диапазона (15 байт `0xFF`).

Если корректная запись не найдена, но кольцо не пустое, резервирование следует считать ошибочным: нельзя молча объявлять повреждённое кольцо пустым.

После обхода восстанавливается кэш поиска активного кольца, чтобы не менять состояние рабочего механизма памяти.

### 3.4. Завершение Backup

После успешной записи и проверки выбранного внутреннего слота:

- показать штатное сообщение о завершении резервирования;
- установить `menu = 0`;
- установить `actencf = true`;
- обновить `actenc = millis()`.

Далее работает существующий механизм `storetomem()`: после штатного таймаута 10 секунд текущие рабочие настройки сохраняются в AT24C32 через `memory(MEM_WRITE)`. Существующее условие запрета сохранения во время передачи (`!txen`) остаётся без изменений.

Backup сам не вызывает `memory(MEM_WRITE)` и не меняет содержимое AT24C32.

## 4. Восстановление Restore

### 4.1. Обязательная проверка до очистки

Сначала проверяется только выбранный слот внутренней EEPROM:

- сигнатура, версия и идентификатор слота;
- маркер завершения;
- CRC16 всего образа;
- допустимость сохранённого номера диапазона;
- каждая из 31 диапазонных записей: либо все 15 байт равны `0xFF`, либо сигнатура и CRC-8 корректны.

Если хотя бы одна проверка не пройдена, AT24C32 вообще не трогается. Никакого автоматического перехода к другому слоту нет.

### 4.2. Стирание внешней AT24C32

После успешной проверки образа очищаются все 4096 байт внешней AT24C32 значением `0xFF`.

Операция выполняется строго побайтно:

1. Записать `0xFF` по текущему адресу через существующий интерфейс библиотеки.
2. Немедленно прочитать тот же адрес.
3. Убедиться, что прочитано именно `0xFF`.
4. Только после этого переходить к следующему адресу.

Если чтение вернуло любое значение, отличное от `0xFF`, очистку и восстановление немедленно прекратить. На дисплее показать:

`Замените микросхему AT24C32`

Продолжать запись резервной копии после ошибки очистки запрещено.

Отдельной команды полного стирания у AT24C32 в используемом интерфейсе нет. Используется существующая побайтная запись библиотеки; её механизм выборочной записи пропускает байты, уже равные `0xFF`.

### 4.3. Запись образа во внешнюю AT24C32

Только после успешного стирания всех 4096 байт записываются:

1. Общие настройки в прежнее расположение: структура по адресам 2–39, контрольная сумма по адресам 0–1. Формат старой суммы сохраняется: сумма 38 байт плюс `crcmod`.
2. Единственная актуальная запись каждого непустого диапазона — с позиции 0 соответствующего кольца.
3. Пустые диапазонные кольца остаются заполненными `0xFF`.
4. Журнал выбора диапазона — одна запись с восстановленным номером `band`, номером события 0 и штатной CRC-8, в начале служебного кольца.

Родные 15-байтовые диапазонные записи не пересоздаются и не перенумеровываются: они переносятся из проверенного образа без изменения содержимого. Активное кольцо содержит запись, сформированную при Backup из RAM.

Адресная карта AT24C32 остаётся прежней:

| Адреса | Назначение |
|---|---|
| 0–1 | Старая контрольная сумма общих настроек |
| 2–39 | `general_setting` |
| 40–4007 | 31 диапазонное кольцо по 128 байт |
| 4008–4095 | Журнал выбора диапазона размером 88 байт |

### 4.4. Проверка после записи

После заполнения AT24C32 выполняется полное чтение всех 4096 байт и сравнение с ожидаемым восстановленным образом:

- общие настройки и старая контрольная сумма;
- единственная запись в начале каждого непустого кольца;
- все остальные байты диапазонных колец равны `0xFF`;
- единственная запись выбора диапазона в начале служебного кольца;
- все остальные байты служебного кольца равны `0xFF`.

Дополнительно проверяются CRC-8 диапазонных записей и CRC-8 записи выбора диапазона.

При любой ошибке проверки восстановление не объявляется успешным и МК не перезагружается для штатной работы с непроверенными данными.

После полного успеха выводится сообщение об успешном восстановлении и выполняется существующий программный переход на начало программы:

```cpp
asm volatile("jmp 0x00");
```

### 4.5. Сообщения дисплея

Интерфейс остаётся русскоязычным. Единственное техническое название, оставляемое без перевода, — `AT24C32`.

В начале Restore используется существующий способ инициализации вывода: очистка экрана, курсор в начале и масштаб 1. Далее сообщения выводятся последовательными вызовами `display.print()` и `display.update()` без повторных `clear()`, `setCursor()` и `setScale()`.

Последовательность сообщений:

1. `Проверка бекапа`
2. `Стирание AT24C32`
3. `Запись настроек`
4. `Проверка записи`
5. Сообщение об успешном восстановлении.

При ошибке очистки выводится `Замените микросхему AT24C32`.

Проценты, прогресс-бары и декоративные элементы не используются.

## 5. Расчёт времени и ресурсов

### Внутренняя EEPROM

- Один слот: 510 байт.
- Два слота: 1020 байт.
- Ёмкость EEPROM ATmega328P: 1024 байта.
- Остаётся: 4 байта.

Полный образ не размещается в отдельном массиве RAM. Работа выполняется потоком: внутренние данные читаются или записываются по адресам; для диапазонной записи используется небольшой буфер в 15 байт.

### Внешняя AT24C32

Ёмкость: 4096 байт.

В библиотеке `Eeprom24C32_64.cpp` физическая запись одного изменяемого байта сопровождается `delay(10)`. Поэтому верхняя оценка задержки только на физическую запись при стирании всех байтов:

`4096 × 10 мс = 40 960 мс ≈ 41 с`.

К этому добавляется время I²C-обмена и чтения каждого байта сразу после записи. Затем выполняется запись восстановленных данных и полная проверка чтением. При записи восстановленного образа максимальное число значащих байтов — 40 байт общих настроек с суммой, 465 байт диапазонных записей и 3 байта журнала выбора, всего 508 байт; пустые диапазоны сокращают это количество.

Ожидаемая длительность — порядка минуты или меньше при исправной шине и микросхеме, но окончательное время определяется фактической скоростью работы конкретной AT24C32 и I²C.

## 6. Что не меняется

- Форматы `general_set` (38 байт) и `band_set` (13 байт).
- Формат диапазонной записи AT24C32 (15 байт) и её CRC-8.
- Алгоритм поиска самой свежей записи в кольце.
- Размеры и адреса кольцевых областей AT24C32.
- Формат журнала выбора диапазона.
- Существующие пункты меню и их счётчики подтверждения.
- Штатный десятисекундный механизм сохранения `storetomem()`.
- Аппаратная библиотека AT24C32 и её интерфейс.

Будущая доработка меню сможет передавать в `backup(slot)` и `restore(slot)` номер слота 1 или 2. Для этого формат резервной копии и сами процедуры менять не потребуется.
